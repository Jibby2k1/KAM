# Phase 6 repository write-up

Phase 6 adds a clean experimental surface for sparse separable memory without changing the historical KAM model. The new surface keeps routing, local expert retrieval, algebra updates, geometry updates, diagnostics, resource accounting, and manifests explicit so later comparisons can be audited.

The local and HPG Stage 0 validity gate passed 128 deterministic rows, and the corrected full Stage 1 mechanism campaign completed 3,000/3,000 HPG rows with independent identity and alternating-schedule audits passing. Bounded Stages 2–6 are also complete and locally retrieved: 48 transformer rows, 32 router rows, 48 corrected online-adaptation rows, 12 corrected capped-training rows, and 12 confirmation-preparation rows. These are implementation, resource, and screening results—not a memory-quality promotion.

Start with `LLM_NAVIGATION.md`, then read `docs/codex/KAM_PHASE6_SPARSE_SEPARABLE_MEMORY_BRIEF.md`. The machine-readable campaign summary is `configs/phase6/phase6_campaign_overview.yaml`; the immutable Stage 0 configuration is `configs/phase6/stage0_validity.yaml`. Local results are under `results/phase6/stage0/`, and the concise ChatGPT handoff is `reports/phase6/PHASE6_LLM_HANDOFF.md`.

The safe expansion order is: HPG Stage 0 profile → measured resource report → Stage 1 mechanism matrix → transformer-scale comparisons → router scaling/online/long-training confirmation. Large arrays should not be submitted merely because the local correctness gate passes.
