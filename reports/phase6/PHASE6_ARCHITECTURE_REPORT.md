# Phase 6 architecture report

The repository now exposes a common modern decoder shell and named controls: T0, widened Transformer, memory tokens, MoE, PKM, fixed-key KAM, learned-key KAM, alternating/variable-projection metadata, online, and dual persistent/episodic memory. Sparse KAM supports exact/chunked routing, product-key and optional approximate routing, vector/affine/low-rank/shared-basis/routes-only values, explicit geometry modes, and a zero-init residual gate. Stage 2 rows now carry a declared 2M/10M/30M total-parameter budget; the builder analytically selects per-architecture width, depth, and FFN settings, and each run records total parameters, routed active parameters, and match error. T-WIDE enlarges the FFN at the matched budget, while T-MOE uses a declared four-expert control rather than silently scaling experts with the memory-slot field.

The first corrected Stage 1 profile exercised T0, T-WIDE, T-MEMTOK, T-KAM-F, and T-KAM-L with explicit geometry factors, but is superseded because task and optimizer dispatch were not faithful to the manifest. The task-aware replacement (`38040026` / `38040027`) passed the identity audit and includes all five architecture labels. The corrected full campaign (`38042710` / `38042711`) completes the balanced mechanism screen and schedule audit; architecture quality claims still require the Stage 2 comparison grid and matched active parameters/FLOPs/wall-clock.
