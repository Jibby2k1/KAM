# Supplying the correct hop count to the learned MuSiQue decomposer

Giving the same learned checkpoints the correct hop count made every decoded output have the intended number of segments. Complete four-hop evidence remained 12–19 of 160 across the three seeds. The unconstrained route recovered 13–18. Forcing the count also reduced the number of plans with valid backward references.

The decoder was constrained at generation time. It blocked EOS while any separators remained, blocked further separators once the desired count was reached, and forced a separator after 36 tokens in an unfinished nonfinal segment. It received the author hop count in this labeled diagnostic. Subquestion wording and bindings were still generated by the frozen models. The same parser, hybrid fallback, initial dense 64, total 128-candidate budget, fixed reader, corpus, and checkpoint were used for the corresponding seed.

On four-hop questions the unconstrained outputs had exactly four steps in 37, 46, and 36 cases. The constrained decoder reached 160 for each seed, with valid four-step plans in 115, 109, and 108 cases. Complete-chain differences on this slice were one gain, one loss, and one loss, with all three paired shared-evidence bootstrap intervals spanning zero. The change combines an oracle count with a constrained decoding policy. In this test a correct count alone failed to produce usable dependency paths.
